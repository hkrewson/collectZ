# collectZ v3.25.1

## Version and date

- Version: `3.25.1`
- Date: `2026-10-21`

## Milestone target and status

- Roadmap slice: `3.25.1 — Node.js October 2026 Security Release`
- Status: implementation and local verification complete; hosted release gates pending.

## Summary

Moves CollectZ's Node 24 runtime, build, CI, and operational helper environments to Node `24.22.1`, the security-fixed Node 24 maintenance-LTS release. The previous canonical backend container was running Node `24.21.0`, which predates the October 21 security release.

## What changed

- Pin backend and frontend build images, syslog and sizing helper images, and the local dependency-audit image to `node:24.22.1-alpine`.
- Pin active Node-based GitHub Actions workflows to Node `24.22.1` and add `.nvmrc` for maintainers.
- Raise the declared minimum backend engine to `>=24.22.1 <25` and add source-contract coverage for all maintained runtime and CI selectors.
- Update the backend and frontend `follow-redirects` override from `1.16.0` to `1.16.1` to resolve two newly reported high-severity advisories found during release preflight.
- Document that `npm audit` covers package dependencies, not the Node runtime and its bundled OpenSSL, c-ares, CA certificates, and Undici components.

## Breaking changes

No API, data, or configuration contract changes. Maintainers running the backend directly must use Node `24.22.1` or a later Node 24 security patch.

## Environment/config changes

No new environment variables. Existing deployments must pull/rebuild the `3.25.1` backend image and recreate the backend container to replace the old embedded Node runtime; changing a moving image tag without recreating the container does not update a running Node process.

## Migration and data impact

No database migration or data change.

## Deployment and verification

Version metadata and Help > Releases are synchronized to `3.25.1`. The recreated canonical `collectz-private` backend reports Node `v24.22.1`, app version `3.25.1`, and `follow-redirects` `1.16.1`; backend/frontend are healthy, `/api/health` reports `3.25.1`, and Help > Releases serves it as the newest entry. ## Security vulnerability triage

- High findings: `0` after remediation in backend and frontend production dependency audits.
- The pre-update production audits identified `follow-redirects@1.16.0` (used through Axios) for cross-origin credential stripping and sensitive-header regex issues (GHSA-q3jh-wrc6-jgq8 and GHSA-8r9p-f939-6h3c); both apps now lock `1.16.1`.
- The Node.js October 21, 2026 release lists four high-severity issues affecting Node 24: NUL-containing DNS names (`CVE-2026-105482`), TLS hostname validation bypasses (`CVE-2026-105483`, `CVE-2026-106069`), and a Brotli decoder out-of-bounds write with potential remote code execution (`CVE-2026-111497`). It also fixes three medium-severity issues (`CVE-2026-105481`, `CVE-2026-106072`, `CVE-2026-106074`) and one low-severity permission-model bypass (`CVE-2026-106073`).
- The release also updates c-ares, CA certificates, OpenSSL, and Undici for the Node 24 line. Node package audits alone do not detect these runtime-bundled components.
- CollectZ uses outbound HTTPS integrations and Node cryptographic APIs. Code-path reachability differs by issue; regardless, each CollectZ Node process included the affected runtime before this patch. The normal CollectZ runtime does not enable Node's Permission Model or startup snapshots/SEA; no claim is made that those issue-specific paths were exercised.
- Fixed by upgrading the Node runtime/build baseline to `24.22.1`; no application-level workaround or data repair is required.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.25.1`.

## Risks and follow-up

- Hosted CI must confirm `compose-smoke`, `rbac-regression`, `browser-regression`, `runtime-smoke`, `dependency-scan`, `secret-scan`, and `image-security-and-sbom` before release publication.
- The sibling Cairn repository owns a separate control-plane Node runtime and needs independent review.
- Direct-host Node users must update to Node `24.22.1` or a later security-fixed Node 24 release.

## Rollback guidance

If the patched base image causes an unexpected compatibility issue, restore the previous application image only as a time-limited emergency measure and isolate the exposed deployment while selecting a security-fixed Node 24 image. Do not roll back to a vulnerable Node runtime for ordinary operation.

## Known issues and follow-up

- The sibling `cairn` repository owns its separate control-plane runtime and must independently adopt a security-fixed Node release if it uses an affected Node 24 build.
- Hosts that run CollectZ scripts or the backend directly outside Docker must install Node `24.22.1` or a later Node 24 security patch; `.nvmrc` records the current project baseline.
