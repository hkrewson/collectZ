- Roadmap slice: `3.24.12 - Sensitive Operation Reauthentication Contract`
- Status: `complete locally; hosted release gates pending`

## Summary

This release makes CollectZ credential and support-delegation operations require a recent password confirmation bound to the current opaque browser session. A reviewed operation inventory now separates harmless masked status from key/token creation, rotation, revocation, provider testing, identity changes, and delegation, with machine-checked authority and disclosure policy.

## What changed

- Added a rate-limited `POST /api/auth/reauthenticate` endpoint that verifies the current password and stamps only the current browser session for a configurable 15-minute window.
- Existing sessions upgrade without proof and therefore fail sensitive operations closed; fresh password logins start with recent proof.
- Added reusable middleware that rejects stale or non-session credentials with the stable `recent_reauthentication_required` reason before protected mutation.
- Guarded personal access token and service-account key create/revoke, platform and workspace integration credential saves/tests, Plex display/webhook token operations, support-session start, and profile email change.
- Kept password change protected by its equivalent current-password proof and other-session revocation; support-session end remains an unguarded safety off-ramp.
- Added a 20-operation reviewed contract covering permissions, CSRF, limiter, session authentication, reauthentication, disclosure, and audit behavior. SMTP and MFA/recovery material are explicitly recorded as unavailable with mandatory future policy.
- Added shared frontend password prompting and exact-operation retry for guarded profile and integration actions.
- Added live PostgreSQL proof for safe status readback, stale and sibling-session non-mutation, CSRF, wrong-password, non-session, support-delegation, limiter, and audit-retention behavior.

## Breaking changes

- High-impact credential and support-session start operations now return `403` with code `recent_reauthentication_required` when the current browser session lacks recent password proof.
- API clients using PAT, service-account, mobile, or legacy bearer credentials cannot establish or use recent browser-session proof.

## Environment/config changes

- Added optional `REAUTH_MAX_AGE_MINUTES` (default `15`).
- `RATE_LIMIT_AUTH_MAX` now also covers password-confirmation attempts.
- The canonical development stack remains `collectz-private` on port `3201`.

## Migration and data impact

- Migration `122` adds nullable `user_sessions.reauthenticated_at`.
- Existing sessions remain valid for ordinary use but start stale for sensitive operations.
- The proof timestamp is session-local and contains no submitted password or derived credential material.
- Rollback to `3.24.11` may leave the nullable column in place harmlessly; snapshot restore remains the certified rollback procedure.
