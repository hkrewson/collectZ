- Roadmap slice: `3.31.2 — Enriched Blu-ray Edition Review and Explicit Apply`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Turns authenticated Blu-ray collection receipts into an evidence-first review workflow. Browser companion `0.3.0` validates and enriches each collection row from its exact Blu-ray.com product page, while CollectZ exposes edition identity, format, identifiers, technical facts, source links, and provenance before any import can be included or applied.

## What changed

- Traverses numeric pages within the same filtered collection so one collector run remains one batch.
- Treats a verified `My Collection` page as owned-collection evidence and records that ownership basis separately from product detail evidence.
- Fetches product details sequentially with conservative delay, validates exact Blu-ray product identity, and retains bounded release, identifier, format, edition, cover, specification, rating, and source evidence.
- Shows honest enriched, partial, and failed states across Editions, Technical, Source, and Provenance review tabs.
- Starts every enriched owned edition Pending and requires an explicit reviewer Include decision.
- Rejects Apply when no reviewed editions are included instead of reporting an empty success.

## Breaking changes

None. Existing single-title Capture Inbox behavior and reviewed Work/Edition/Owned Copy storage remain compatible. New collection runs require browser companion `0.3.0` to produce import-eligible enrichment evidence.

## Environment/config changes

None. The browser companion continues to use the existing CollectZ extension token and the user's active Blu-ray.com browser session. Provider credentials and cookies are never submitted.

## Migration and data impact

No database migration is required. Enrichment evidence is stored in the existing bounded `capture_items.source_context` contract. Proof-of-concept batches created before this contract may remain visible but are not import-eligible without rerunning the collector.

## Deployment and verification

The canonical `collectz-private` stack on port `3201` is the required runtime target. Closeout verifies browser companion `0.3.0`, OpenAPI, backend and frontend tests/builds, enriched batch smoke, rendered desktop/mobile review evidence, canonical runtime, Help > Releases, relevant RBAC/browser/runtime gates, and the local release gate.

## Security vulnerability triage

- High findings: none in the backend or frontend production dependency audits; local CodeQL reported zero active results.
- Authorization impact: unchanged exact-library actor-authorized RLS boundary.
- Session boundary: product requests execute inside the active browser session; credentials, cookies, headers, and raw HTML remain browser-local.
- Evidence boundary: only bounded allowlisted identifiers, release fields, technical facts, ratings, URLs, and provenance are retained.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.2` before release publication.

## Rollback guidance

Deploy matching CollectZ `3.31.1` backend/frontend and browser companion `0.2.1`. Migration `150` remains additive and compatible. Rows captured with the enriched contract remain non-destructive review evidence if the application is rolled back.

## Known issues and follow-up

Detail enrichment remains a manually initiated, deliberately paced browser-session workflow. Non-owned provider states, scheduled traversal, normalized price history, notifications, upgrades, Plex propagation, and additional providers remain backlog work.
