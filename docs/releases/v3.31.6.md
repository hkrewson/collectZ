# collectZ v3.31.6

## Version and date

- Version: `3.31.6`
- Date: `2026-11-28`

## Milestone target and status

- Roadmap slice: `3.31.6 — Reviewed Work and Edition Identifier Registry`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Promotes reviewed title and product identifiers into a normalized registry attached to the Work or Edition they actually identify, while preserving immutable capture evidence.

## What changed

- Adds a typed, exact-library Object Identifier registry with source-observation provenance.
- Stores IMDb title IDs on Works and Blu-ray product, content/group, UPC/EAN, and ASIN values on Editions.
- Makes repeat Apply identifier-idempotent and rejects strong cross-target collisions for review.
- Backfills unambiguous identifiers from existing reviewed Blu-ray editions and observations.
- Keeps category IDs as classification evidence instead of misrepresenting them as object identity.

## Breaking changes

None. Browser companion `0.3.2` remains compatible and unchanged.

## Environment/config changes

None.

## Migration and data impact

Migration `151` adds `collection_object_identifiers` with exact-library foreign keys, RLS, target constraints, and documented exclusive indexes. Migration `152` backfills reviewed Blu-ray product and normalized observation identifiers. Migration `153` recovers UPC/EAN values from the exact matching legacy product variant because older observations predate those normalized facts. Ambiguous IMDb evidence is deliberately skipped rather than guessed. Work or Edition deletion cascades its identifiers; deleting an observation clears only the provenance pointer.

## Deployment and verification

The canonical `collectz-private` stack on port `3201` is the runtime target. Closeout verifies fresh migration parity, retained-data backfill, apply-time promotion, replay idempotency, collision behavior, lifecycle cleanup, workspace ownership, version/release-feed alignment, and relevant release gates.

## Security vulnerability triage

- High findings: pending final production dependency audits.
- Authorization impact: the registry uses exact-library actor-authorized RLS and same-library target constraints.
- Session boundary: unchanged; provider session material remains browser-local.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.6` before release publication.

## Rollback guidance

Deploy matching CollectZ `3.31.5` backend/frontend. The additive identifier table may remain unused, or an operator may remove migrations `152` and `151` only through a reviewed database rollback. Canonical Works, Editions, Owned Copies, observations, and compatibility data remain unchanged.

## Known issues and follow-up

The registry currently promotes reviewed Blu-ray intake only. Global identifier search, automatic weak-identifier matching, provider-category normalization, non-owned states, price/rating history, upgrade discovery, notifications, Plex propagation, and additional provider adoption remain separate work. The local release preflight remains NO-GO only because observability evidence is stale and its refresh requires a separately authorized monitoring/logging infrastructure rehearsal; hosted secret, image/SBOM, Compose, and Core runtime gates must also rerun after push.
