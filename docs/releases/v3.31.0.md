# collectZ v3.31.0

## Version and date

- Version: `3.31.0`
- Date: `2026-11-25`

## Milestone target and status

- Roadmap slice: `3.31.0 — Reviewed Blu-ray Work, Edition, and Owned Copy Foundation`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Begins the broader Work/Edition/Owned Copy program through the existing reviewed single-title Blu-ray intake flow. One movie title can now own exact Blu-ray Editions and idempotent library copies while current media and variant behavior remains compatible.

## What changed

- Adds exact-library Work, Edition, Owned Copy, and immutable Edition Source Observation records behind additive migration `148`.
- Uses Blu-ray.com product identity to upsert one exact Edition and the Capture Inbox receipt to create at most one Owned Copy.
- Retains normalized release facts as immutable edition evidence and appends a new observation only when the normalized evidence changes.
- Rejects silent Edition reassignment and cross-workspace/library relationships.
- Keeps `media` and `media_variants` as compatibility projections so existing title, owned-format, identifier, cover, trailer, and valuation behavior continues.
- Shows the Work, Edition, and Owned Copy outcomes in the Capture Inbox before apply and returns their created/reused identities afterward.

## Breaking changes

None. Existing records are not backfilled or split, and non-Blu-ray import paths continue unchanged.

## Environment/config changes

None. The browser companion continues to use the existing capture-specific authentication and does not send Blu-ray.com credentials or session cookies to CollectZ.

## Migration and data impact

Migrations `148` and `149` create four additive tables, exact-scope foreign keys and indexes, row-level security policies, and append-only observation controls. Deleting a converted capture clears only the observation's capture pointer; deleting its Edition through the normal Work lifecycle removes the dependent evidence through an authorized cascade. Existing media and variant rows are not rewritten. The migrations are forward-only; older application versions ignore the new tables.

## Deployment and verification

The canonical `collectz-private` stack was rebuilt and recreated in place on port `3201` with migration `149` and version `3.31.0`. The reviewed Blu-ray ownership smoke passed in both Core and Platform modes, including idempotent replay, changed-evidence append, capture cleanup retention, authorized lifecycle cleanup, sibling-library RLS denial, and cross-library relationship denial. Core RBAC, Core and Platform edition boundaries, tenancy boundaries, workspace ownership, the live Help > Releases feed, the maintained browser regression, unit/OpenAPI/frontend checks, production dependency audits, migration and identity certifications, observability evidence, release preflight, and the standard local release gate pass.

Local CodeQL remains blocked by an incompatible installed query-pack/data-extension combination. Local `gitleaks` and Trivy/SBOM gates are blocked because those tools are not installed. The production-shaped secure-cookie Compose assertion is intentionally blocked by the canonical development stack's `NODE_ENV=development` and `SESSION_COOKIE_SECURE=false`; hosted CI must rerun `compose-smoke`, CodeQL, `secret-scan`, `image-security-and-sbom`, and the complete release workflow after push.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits report zero low, moderate, high, or critical vulnerabilities.
- Authorization impact: all four new record types require an actor-authorized exact-library database transaction and composite same-workspace/library relationships.
- Evidence hygiene: Edition Source Observations retain bounded normalized facts, hashes, provider/product identity, and capture linkage; they do not retain credentials, cookies, or an unbounded raw browser payload.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.0` before release publication.

## Rollback guidance

Deploy the matching `3.30.0` backend and frontend together if application rollback is required. Leave migration `148` applied; its additive rows and immutable observations remain safe and are ignored by `3.30.0`. Corrective schema changes must use a new forward migration.

## Known issues and follow-up

This release covers one reviewed single-title owned Blu-ray capture. Authenticated collection traversal, batch review, status mapping, multiple-copy editing, upgrade discovery, price history and alerts, Plex watched-state propagation, broad provider adoption, and existing-variant backfill remain future milestones. Hosted certification and publication also remain pending until an authorized push.
