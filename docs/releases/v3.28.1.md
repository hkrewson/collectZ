# collectZ v3.28.1

## Version and date

- Version: `3.28.1`
- Date: `2026-11-15`

## Milestone target and status

- Roadmap slice: `3.28.1 — BookOrbit Rich Comic Series Metadata`.
- Status: release candidate. Local certification is complete; hosted publication and the annotated release tag remain pending.

## Summary

Extends the BookOrbit adapter with capability-gated native metadata, upstream comic identifiers, normalized multi-series membership and provenance, stable membership retirement/reactivation, and credential-safe native cover enrichment while retaining OPDS fallback and canonical BookOrbit identity.

## What changed

- Added optional encrypted BookOrbit native API authentication and read-only `/api/v1/books/{id}` enrichment derived only from validated BookOrbit Atom identities.
- Preserved BookOrbit-scoped ComicVine, Goodreads, and other upstream identifiers as compatibility metadata without treating them as alternate canonical identities or inferring an unavailable selected-provider field.
- Added normalized provider-series records and canonical-media memberships capable of representing multiple ordered series, series index, volume, issue number, expected item count, source timestamps, provenance, and active/deactivated lifecycle.
- Added repeat-sync refresh semantics that update or reactivate observed memberships, retire missing memberships and orphaned provider-series observations, and leave prior native observations unchanged when a per-publication native request falls back to OPDS.
- Kept the first ordered membership projected into existing scalar series fields during compatibility migration without fabricating issue numbers from OPDS ordering.
- Added native cover provenance and a versioned, session-only CollectZ cover proxy that resolves encrypted credentials at request time, verifies the imported BookOrbit identity, bounds response type and size, and never exposes the upstream API key.
- Added active multi-series and provenance readback to media detail plus a Library drawer presentation for series position, expected item count, source, and update time.
- Added migration, RLS, ownership, transport, authoritative import, OpenAPI, frontend, and release certification coverage for the new relational and cover paths.

## Breaking changes

No intended API or user-facing breaking changes. Existing BookOrbit OPDS imports, Atom provider identity, acquisition links, cover fallback, scalar series/issue/volume fields, manual field controls, synchronous import responses, and durable scheduled synchronization remain compatible. The richer `series_memberships` detail projection is additive.

## Environment/config changes

No new required environment variables. Existing BookOrbit connections may add the optional encrypted native API key to enable native metadata and covers. Connections without that key continue using the certified OPDS representation.

## Migration and data impact

Migration `136` adds workspace-owned `provider_series_records` and `media_series_memberships` tables with same-workspace foreign keys, observation/lifecycle timestamps, uniqueness constraints, indexes, and RLS. Existing media rows are not rewritten on upgrade. Normalized memberships are populated when a BookOrbit item is successfully observed through native enrichment; unavailable native responses do not remove prior relational observations.

## Rollback guidance

Deploy the matching `3.28.0` backend and frontend together and disable BookOrbit automatic sync targets before rollback if native enrichment is causing repeated provider failures. Do not delete Provider Connections, External Identities, Canonical Field Controls, `provider_series_records`, `media_series_memberships`, or BookOrbit compatibility values created or observed by `3.28.1`; preserving additive records keeps identity, provenance, lifecycle, and later forward-deployment behavior deterministic. Follow the reviewed migration rehearsal if a schema rollback is required.

## Known issues and follow-up

BookOrbit does not currently expose a reliable selected-metadata-provider field, so upstream provider identifiers remain provenance metadata while BookOrbit stays canonical. Scalar series fields intentionally remain first-membership compatibility projections. BookOrbit writeback, provider-file mutation, and broader work/edition/copy remodeling remain out of scope.
