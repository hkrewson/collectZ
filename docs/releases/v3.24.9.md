## Summary

This release makes authentication and invitation audit details fail closed to an explicit minimal catalog. It removes account-discovery and credential-adjacent values from security audit payloads, adds focused invitation mutation throttling and CSRF proof, and inventories legacy plaintext invitation state without exposing invitation identities or token values.

## What changed

- Every maintained authentication, mobile-auth, invitation, membership/ownership-transfer, CSRF, support-scope, and scope-denial activity action now has an explicit detail-key and value-type schema.
- Unknown detail fields are rejected before database persistence and structured-log export; uncataloged future security-sensitive actions retain no details until deliberately classified.
- Security audit callers no longer submit account or membership email addresses, token-row identifiers, profile before/after values, device names, support-requester addresses, ownership-transfer labels, or free-form SMTP errors.
- Generic request-outcome audit rows retain only method, query-free path, status, and duration, without response bodies or original query strings.
- Workspace invitation creation and revocation have a dedicated application-layer limiter controlled by `RATE_LIMIT_INVITE_MAX`.
- Concurrent claims for the same invitation token are serialized so the losing request receives the deliberate invalid-token response instead of racing into a duplicate-account error.
- Live auth abuse verification covers invitation create/revoke CSRF non-mutation, invitation limiter exhaustion, persisted detail-key allowlists, and tested sensitive-value absence.
- A read-only invitation-token inventory reports aggregate active plaintext, missing-hash, and historical plaintext counts without selecting invite identities or values.

## Breaking changes

- No API response contract is intentionally removed.
- Operators who relied on free-form auth failure response bodies or submitted addresses inside `activity_log.details` must instead use request correlation, safe reason codes, actor/entity identifiers, and authorized user administration.

## Environment/config changes

- Added optional `RATE_LIMIT_INVITE_MAX`; the production default is `20` mutations per `RATE_LIMIT_WINDOW_MINUTES` window.
- Existing global and authentication limiter settings remain independently enforced.
- The canonical development stack remains `collectz-private` on port `3201`.

## Migration and data impact

- No schema migration is required.
- Existing historical audit rows are not rewritten.
- The legacy plaintext invitation lookup remains temporarily available; this release inventories its dependency state but does not remove it.
