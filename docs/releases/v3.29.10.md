## Summary

Adds an explicit, atomic way to apply still-current approved BookOrbit or Kavita observation fields to CollectZ while preserving immutable before/after evidence and preventing automatic future overwrite.

## What changed

- Added exact-preview fingerprints and stale-plan rejection for approved provider metadata.
- Applies all still-eligible approved fields atomically and records reviewed, preserve-only field authority.
- Added immutable exact-library-scoped apply events with bounded before/after field evidence.
- Added Provider history confirmation, loading, blocker, success, and applied-history states.
- Surfaces selected metadata-provider ids, observed series memberships, and cover provenance alongside reviewable canonical differences.
- Keeps provider writeback, automatic refresh, cover application, identity rematching, and provider selection out of scope.

## Breaking changes

None. The apply endpoint, event ledger, and Provider history controls are additive.

## Environment/config changes

None.

## Migration and data impact

Migration `147` adds the append-only `provider_observation_apply_events` table with exact workspace, library, media, and observation ownership plus row-level security. Existing media and observation rows are not backfilled or changed by the migration.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: preview, apply, and history execute only inside exact authorized workspace/library scope and return a non-disclosing not-found response outside it.
- Evidence hygiene: ordinary apply readback omits actor ids, review ids, workspace/library implementation ids, credentials, endpoints, raw provider payloads, and authorization state.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.10` before release publication.

## Rollback guidance

Deploy the matching `3.29.9` backend and frontend together. The additive apply-event table may remain unused; do not delete successful audit evidence during application rollback.

## Known issues and follow-up

Apply is a deliberate one-time CollectZ update. Automatic rematching, provider writeback, historical observation backfill, cover review/application, and work/edition/owned-copy modeling remain separate future work.
