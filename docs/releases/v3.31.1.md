# collectZ v3.31.1

## Version and date

- Version: `3.31.1`
- Date: `2026-11-26`

## Milestone target and status

- Roadmap slice: `3.31.1 — Authenticated Blu-ray Collection Traversal and Batch Edition Review`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Extends reviewed Blu-ray intake from one title at a time to a bounded, resumable collection workflow. The browser companion traverses pages with the user's existing provider session, submits normalized edition evidence without credentials or cookies, and CollectZ presents one conflict-first review batch before any owned records are applied.

## What changed

- Adds exact-library collection batch receipts and duplicate-safe child intake records through additive migration `150`.
- Adds authenticated Blu-ray.com traversal to browser companion `0.2.0`, with sequential page requests, jitter, a 100-page ceiling, and safe pauses for sign-in, challenge, rate-limit, forbidden, empty, or network responses.
- Keeps provider cookies and credentials in the active browser tab; only bounded title, product identity, status, format, year, source URL, and capture timing evidence reaches CollectZ.
- Groups a traversal into one Capture Inbox batch row with conflict-first review, a full-set toggle, keyboard-accessible edition navigation, and explicit Include or Skip decisions.
- Applies only rows with an explicit Owned status. Each included row independently reuses the existing reviewed single-title path and therefore retains Work, Edition, Owned Copy, cover/format compatibility projection, and immutable source provenance behavior.
- Preserves successful rows when a sibling row fails and leaves failed rows available for retry.

## Breaking changes

None. Existing Capture Inbox records and the single-title browser capture flow continue unchanged.

## Environment/config changes

None. Browser companion `0.2.0` uses the existing CollectZ extension token and requires no Blu-ray.com API credential. The user must already be signed in to Blu-ray.com in the active tab.

## Migration and data impact

Migration `150` creates `capture_batches`, adds optional batch linkage fields to `capture_items`, and establishes exact workspace/library foreign keys, indexes, and row-level security. Existing capture rows remain ungrouped and are not rewritten. Batch child rows are hidden from the ordinary Capture Inbox list and remain addressable through their batch receipt.

## Deployment and verification

The canonical `collectz-private` stack on port `3201` is the required verification target. Local closeout verifies migration `150`, authenticated batch endpoints, independent reviewed apply, version/readiness metadata, the Help > Releases feed, unit and OpenAPI contracts, frontend and browser companion builds, workspace ownership, Core RBAC, runtime boundaries, browser regression, and the standard local release gate. Hosted CI must rerun any environment-specific security or image gates documented as blocked in the closeout.

## Security vulnerability triage

- High findings: none in the local production dependency audits.
- Authorization impact: batch receipts are exact-library records protected by actor-authorized row-level security and composite same-scope relationships.
- Session boundary: provider authentication remains browser-local; collection payloads contain no Authorization header, provider cookie, password, or session token.
- Automation boundary: traversal is manual, sequential, bounded, and pauses instead of attempting to bypass provider authentication, challenges, forbidden responses, or rate limits.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.1` before release publication.

## Rollback guidance

Deploy the matching `3.31.0` backend and frontend together if application rollback is required. Leave migration `150` applied; it is additive and older application versions ignore grouped batch records. Corrective schema work must use a new forward migration.

## Known issues and follow-up

This release maps only explicit Owned collection status. Broader provider status mapping, provider detail-page enrichment during traversal, scheduled crawling, upgrade discovery, price history and alerts, Plex propagation, additional providers, and historical backfill remain unscheduled backlog work.
