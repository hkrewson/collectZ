# collectZ v3.28.0

## Version and date

- Version: `3.28.0`
- Date: `2026-11-12`

## Milestone target and status

- Roadmap slice: `3.28.0 — Durable Provider Job Foundation`.
- Status: released. Local and hosted certification passed; annotated tag `v3.28.0` identifies the certified release commit.

## Summary

Introduces a workspace-owned durable PostgreSQL job lifecycle, adopts it for Plex reconciliation and scheduled BookOrbit synchronization, and gives integration operators safe job history, cadence visibility, and cancellation without exposing credentials or provider payloads.

## What changed

- Added stable public job UUIDs, relational workspace/library/provider-connection ownership, idempotency identities, bounded attempts, availability, leases, heartbeats, cancellation, and terminal timestamps while retaining compatibility with existing numeric job IDs.
- Added one shared durable lifecycle for idempotent enqueue, concurrent-safe claim, owner-bound lease renewal, progress, bounded retry/final settlement, cancellation, expired-lease recovery, and workspace-scoped readback.
- Migrated Plex full-library reconciliation to the leased worker lifecycle while preserving its existing safe-update, strong-identifier, and conflict-review behavior.
- Added relational BookOrbit sync targets with enabled cadence, last-enqueue state, scheduled durable execution, current credential resolution at execution time, and duplicate cadence suppression.
- Preserved BookOrbit OPDS series names and ordering, stable provider identity, acquisition and cover links, and lossless provider-owned book/comic classification changes without fabricating issue numbers.
- Added provider-neutral operator APIs and integration panels for recent job state, attempt counts, next eligibility, safe failure summaries, cadence status, and cooperative cancellation.
- Added canonical database, provider, ownership, migration, runtime-role, external-identity, RBAC, browser, and runtime-contract evidence for the durable lifecycle and its first two materially different adopters.

## Breaking changes

No intended API or user-facing breaking changes. Existing synchronous responses, numeric job identifiers, BookOrbit OPDS identity, Plex matching behavior, and provider-specific summaries remain available through compatibility projections while new callers use public job UUIDs and relational ownership.

## Environment/config changes

No new required environment variables. Existing BookOrbit connections can optionally configure automatic synchronization through their workspace-owned sync target. Job targets persist provider-connection references only; credentials remain encrypted in their existing integration stores and are resolved only during execution.

## Migration and data impact

Migrations `134` and `135` add the durable job envelope and BookOrbit provider sync targets. Historical jobs retain their existing payloads and numeric IDs while gaining stable public identity and relational ownership where resolvable. Provider sync targets enforce same-workspace connection/library ownership and use RLS. No canonical media rows are rewritten merely by upgrading.

## Rollback guidance

Deploy the matching `3.27.5` backend and frontend together and disable automatic BookOrbit targets and Plex reconciliation scheduling before rollback. Do not delete durable jobs, provider sync targets, Provider Connections, External Identities, Canonical Field Controls, or compatibility values created or observed by `3.28.0`; preserving the additive records keeps retry, audit, and later forward-deployment behavior deterministic. Follow the reviewed migration rehearsal when a schema rollback is required.

## Known issues and follow-up

Running cancellation is cooperative and becomes terminal when an adapter reaches a checkpoint. The scheduler sweep remains process-local while PostgreSQL idempotency prevents duplicate cadence work across instances. Rich native BookOrbit comic series membership, volume/issue separation, story arcs, credits, provider identifiers, and source provenance are deliberately queued for `3.28.1`; BookOrbit writeback and provider-file mutation remain out of scope.
