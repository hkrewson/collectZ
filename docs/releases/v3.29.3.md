# collectZ v3.29.3

## Version and date

- Version: `3.29.3`
- Date: `2026-11-22`

## Milestone target and status

- Roadmap slice: `3.29.3 — Immutable Provider Source Observations`.
- Status: release candidate. Local implementation, migration authority, retained-stack upgrade, runtime-role certification, version alignment, and release artifacts are complete; hosted certification and automatic tag creation require an authorized push to `main`.

## Summary

Adds an append-only, workspace-owned ledger of normalized provider facts and makes BookOrbit its first transactional adopter.

## What changed

- Added immutable provider source observations tied to one workspace, Provider Connection, external media identity, and observed canonical public UUID.
- Added source kind, schema version, source and observation timestamps, content hashing, and import-batch idempotency without persisting raw provider payloads.
- BookOrbit now records normalized OPDS or native bibliographic facts, upstream provider identifiers, ordered series memberships, and cover provenance in the same authorized transaction as canonical reconciliation.
- Retrying the same durable job with unchanged facts reuses its observation; a later batch or changed normalized facts appends new history.
- Database triggers reject observation updates and deletes, RLS hides rows without an authorized workspace transaction, and same-workspace foreign keys prevent identity/connection crossover.
- The BookOrbit runtime smoke now proves normalized persistence, idempotency, immutability, RLS isolation, and credential-free observation facts alongside the existing identity, metadata, cover, scheduler, and series checks.

## Breaking changes

None. Existing BookOrbit routes, durable-job responses, canonical media fields, series memberships, cover proxy paths, and manual/provider refresh behavior remain compatible.

## Environment/config changes

None.

## Migration and data impact

Migration `145` adds `provider_source_observations`, its indexes, same-workspace foreign keys, append-only trigger, RLS policy, and the external-identity composite key used by observation ownership. Existing media, identities, jobs, provider connections, and metadata are not rewritten. New observations are created only by adopted provider workflows; BookOrbit is the first adopter.

The retained canonical database upgraded from `144` to `145`. Fresh-install migration authority applied all `145` migrations, the `144 -> 145` rehearsal preserved baseline and restored-runtime state, and runtime-role certification passed all `32/32` checks with the new table included in provisioning.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: observations use the existing actor-authorized workspace transaction and workspace RLS; unscoped runtime SQL returns no rows.
- Evidence hygiene: only allowlisted normalized facts are stored. Secret-bearing keys, raw payloads, credentials, authorization headers, and authenticated upstream URLs are rejected or omitted.
- Immutability: database triggers reject both update and delete operations for observation rows.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.3` before release publication.

## Rollback guidance

Deploy the matching `3.29.2` backend and frontend together. The older application ignores the additive observation table, but migration `145` should normally remain applied so already-recorded provenance is retained. If a schema rollback is operationally required, first preserve a database backup and export the observation ledger; dropping migration `145` destroys immutable provenance and is not an application-level rollback requirement.

## Known issues and follow-up

BookOrbit is the only observation adopter in this release. CWA, Kavita, Plex, scanner, valuation, and other provider workflows remain future bounded adoptions. The ledger records normalized source facts and provenance; it does not implement selected-provider inference, automated rematching, or work/edition/owned-copy remodeling.

The local observability release rehearsal is current for `3.29.3` and passed all `9/9` persistence, collector, restore, and health checks. It remains release-facing local evidence rather than a tagged-CI-required artifact.
