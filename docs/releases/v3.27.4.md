# collectZ v3.27.4

## Version and date

- Version: `3.27.4`
- Date: `2026-11-11`

## Milestone target and status

- Roadmap slice: `3.27.4 — BookOrbit OPDS Adapter`.
- Status: local release certification complete; hosted release certification remains required after an authorized push.

## Summary

Adds BookOrbit as a first-class, multi-instance OPDS provider backed by the authoritative external-identity registry. BookOrbit books and comics retain stable provider identity across repeat imports, ISBN corrections, visible-title collisions, and provider-owned book/comic classification changes without being presented as Calibre/CWA records.

## What changed

- Added bounded BookOrbit OPDS discovery and catalog traversal over the shared transport, including Basic authentication, safe same-origin URL resolution, response/page/time limits, cycle detection, and complete-feed validation before mutation.
- Added explicit BookOrbit connection administration with encrypted credentials, redacted readback, credential rotation, test, disable, reactivate, archive, and active-connection import selection.
- Preserved Atom entry ids such as `urn:bookorbit:book:{id}` as connection-scoped External Identities while keeping ISBN and other bibliographic facts mutable and non-identifying.
- Recognized current CBZ and CBR acquisition MIME types, preserved series/index, cover, acquisition, and source-update facts, and skipped unsupported audiobook acquisitions instead of misclassifying them as books.
- Kept distinct provider records separate when ISBN or visible titles collide and added audit diagnostics for duplicates, partial outcomes, provider-identity matches, and guarded strong-identifier conflicts.
- Added controlled Provider Type Transitions: lossless provider-owned book/comic changes retain the Canonical Object, while locked, manual, cross-provider, uncontrolled, or lossy changes preserve the existing object and require review.

## Breaking changes

No intended API or user-facing breaking changes. Existing CWA/Calibre behavior, compatibility provider fields, and current library records remain supported.

## Environment/config changes

No new environment variables are required. Each BookOrbit installation is configured as its own workspace-owned Provider Connection with encrypted OPDS credentials and an optional bounded page limit.

## Migration and data impact

No new database migration is included. BookOrbit uses the Provider Connection, External Identity, Canonical Field Control, and compatibility-projection schema introduced in `3.27.0` through `3.27.3`. Existing BookOrbit canonical rows acquire provider control of `media.media_type` after an unchanged repeat observation; a legacy row that changes type before that observation fails closed for review.

## Rollback guidance

Deploy the matching `3.27.3` backend and frontend together and disable BookOrbit imports while rolling back application code. Do not delete Provider Connections, External Identities, Canonical Field Controls, or compatibility values created by `3.27.4`; they are compatible with the additive `3.27.3` schema and preserve the evidence needed to resume safely.

## Known issues and follow-up

BookOrbit audiobook acquisitions remain intentionally unsupported. Reading progress, metadata writeback, embedded reading, file proxying, and scheduled synchronization remain outside this milestone. Existing digital-library provider adoption continues in `3.27.5`.
