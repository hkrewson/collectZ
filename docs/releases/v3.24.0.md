# collectZ v3.24.0

## Version and date

- Version: `3.24.0`
- Date: `2026-07-26`

## Milestone target and status

- Roadmap slice: `3.24.0 - Node 24 Backend Runtime Baseline`
- Status: `implementation complete; hosted release gates pending`

## Summary

This release restores CollectZ to an upstream-supported runtime baseline by moving the backend, active CI jobs, and operational Node helper images from end-of-life Node 20 to Node 24 LTS.

## What changed

- Moved the production backend Docker image to Node 24.
- Declared Node 24 as the supported backend package engine.
- Made the production backend image use lockfile-strict `npm ci`.
- Aligned active GitHub Actions jobs and scheduled dependency reporting on Node 24.
- Moved the syslog collector and sizing helper images to Node 24.
- Added source-contract coverage that rejects active Node 20 runtime or CI configuration.
- Updated newly disclosed vulnerable transitive development/build dependencies without changing the application dependency architecture.
- Repaired a stale browser fixture and pre-existing maintained-source CodeQL findings exposed by the full release gate.
- Kept the current application architecture: Node/Express/Postgres for the backend and Vite-built static assets served by Nginx for the frontend.

## Breaking changes

- Operators who build or run the backend outside Docker must use Node 24.
- The HTTP API, database schema, environment contract, and user-facing behavior are unchanged.

## Environment/config changes

- No new environment variables are required.
- The supported backend runtime changes from Node 20 to Node 24 LTS.

## Migration and data impact

- No database migration is introduced by the runtime upgrade.
- Existing collection records, users, sessions, uploads, and integration configuration are preserved.
- Init parity and migration rehearsal remain required release gates.

## Deployment and verification

- Root, backend, and frontend lockfiles passed clean installs in disposable Node 24 containers.
- The production backend and sizing images built on Node `24.18.0`; the backend image loaded bcrypt successfully and the source-backed stack became healthy at version `3.24.0`.
- Backend unit coverage passed all `343` checks; OpenAPI, integration smoke, RBAC regression, init parity, migration rehearsal, and both core and control-plane runtime smoke passed.
- The full browser regression passed `69` checks with `4` expected homelab-only skips.
- Observability release evidence passed all `9` persistence, collector, non-blocking failure, restore, and final-health checks.
- The standard local release gate passed all `12` gates. Maintained-source CodeQL reported `5` reviewed results with `0` active findings after remediation and source-local suppression of two hash-validated alternate-auth flows.
- The running stack reported Node `24.18.0`, application/frontend/backend/build `3.24.0`, and served `3.24.0` as the newest Help > Releases entry.

## Security vulnerability triage

- Production backend and frontend dependency audits report `0` low, moderate, high, or critical findings.
- The frontend build lock moved PostCSS from `8.5.15` to `8.5.23` for `GHSA-r28c-9q8g-f849`.
- The backend development lock moved brace-expansion from `5.0.7` to `5.0.8` for `GHSA-mh99-v99m-4gvg`.
- Maintained-source CodeQL has `0` active findings. Two reviewed `js/user-controlled-bypass` results are source-suppressed because the credentials are hash-validated against stored records and then constrained by route scopes.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.0`.
- Node 20 is end-of-life and no longer receives normal upstream security fixes; replacing it is the primary security purpose of this release.

## Blocked or CI-only gates

- Local gitleaks is unavailable, so the repository-history `secret-scan` remains a hosted GitHub Actions gate.
- Local Trivy/SBOM wiring is intentionally deferred by the full local gate, so `image-security-and-sbom` remains hosted-only.
- The local development stack uses `SESSION_COOKIE_SECURE=false` with `NODE_ENV=development`; hosted `compose-smoke` must confirm the production secure-cookie contract.
- Hosted GitHub Actions remains authoritative for the complete publish workflow after this milestone is pushed.

## Rollback guidance

- Roll back backend and operational images to the exact `3.23.21` release if Node 24 produces a runtime incompatibility that escaped verification.
- Do not remain on the Node 20 rollback longer than necessary because it restores service at the cost of returning to an end-of-life runtime.

## Known issues and follow-up

- No Node 24 compatibility issue is known from local verification.
- A backend framework or language rewrite remains out of scope and requires a separate evidence-driven architecture decision.
