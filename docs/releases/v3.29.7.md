## Summary

Makes immutable BookOrbit and Kavita evidence easier to review by showing how allowlisted observed bibliographic facts compare with the current canonical record, without applying metadata or changing provider authority.

## What changed

- Added a derived comparison to each workspace-authorized provider observation readback.
- Compares an explicit allowlist of current and observed bibliographic fields while ignoring blank provider values.
- Normalizes equivalent text, number, identifier, and date representations before reporting differences.
- Returns only differing fields with safe current/observed values and bounded authority, write-mode, lock, and same-provider context.
- Shows match/difference counts and field details in Library Provider history without offering apply or rematch actions.
- Extended unit, OpenAPI, BookOrbit runtime, and browser coverage for comparison behavior and internal-id exclusion.

## Breaking changes

None. The existing provider-observation endpoint adds a required `comparison` object to each observation; it remains read-only and retains the existing authorization and pagination contract.

## Environment/config changes

None.

## Migration and data impact

No migration, backfill, or retained-data rewrite is required. Comparisons are derived from immutable observations, the current media row, and existing canonical-field controls inside the authorized read transaction.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: comparisons are computed only after the media row resolves in the active workspace/library scope and inside the existing authorized observation transaction.
- Evidence hygiene: the projection uses an explicit field allowlist and does not return workspace ids, actor ids, field-control Provider Connection ids, credentials, endpoints, authorization state, or raw provider payloads.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.7` before release publication.

## Rollback guidance

Deploy the matching `3.29.6` backend and frontend together. No schema rollback is needed, and immutable observations remain unchanged.

## Known issues and follow-up

The comparison is advisory and includes only fields present in the normalized observation schema. Applying historical observations, choosing a metadata provider, conflict resolution, identity rematching, and work/edition/owned-copy modeling remain separate future work.
