# collectZ v3.27.5

## Version and date

- Version: `3.27.5`
- Date: `2026-11-11`

## Milestone target and status

- Roadmap slice: `3.27.5 — Existing Digital-Library Provider Identity Adoption`.
- Status: released after local and hosted certification; annotated tag `v3.27.5` identifies release commit `58918f55`.

## Summary

Moves Kavita series and chapter imports onto the authoritative Provider Connection and External Identity model, certifies historical CWA/Calibre and Kavita identity adoption, and introduces one deliberately small identity-payload contract shared by BookOrbit, CWA, and Kavita without flattening their provider-specific behavior.

## What changed

- Added a stable workspace binding for the existing Kavita configuration and retained its encrypted configuration as the compatibility source while migration evidence is gathered.
- Reconciled Kavita series and chapter rows by workspace, Provider Connection, Identity Kind, and normalized numeric record id while keeping existing `kavita:series:{id}` and `kavita:chapter:{id}` compatibility values readable.
- Preserved Kavita library, series, issue, volume/chapter, cover, launch, reader, progress, metadata-writeback, and Canonical Field precedence behavior through authoritative identity adoption.
- Made historical CWA and Kavita adoption prefer their explicit integration binding when multiple same-provider connections exist; missing, inactive, conflicting, or ambiguous ownership remains unchanged for review.
- Added rollback-only live-database certification for exact CWA book and Kavita series/chapter adoption, redacted diagnostics, idempotent reruns, ambiguity refusal, and retained-state restoration.
- Extracted a two-operation digital-library identity-payload module used by BookOrbit, CWA, and Kavita for allowlisted Canonical Field construction and exact Compatibility Projection construction.
- Documented intentional differences in provider identity syntax, connection models, link/cover handling, credential sources, BookOrbit type transitions, and Kavita reader/writeback behavior.

## Breaking changes

No intended API or user-facing breaking changes. Existing provider-specific route names, settings, links, covers, compatibility fields, reader/progress behavior, and metadata-writeback controls remain supported.

## Environment/config changes

No new environment variables are required. Saving an existing Kavita workspace configuration materializes or updates its stable `books.kavita` Provider Connection binding. Existing CWA/Calibre and Kavita encrypted configuration fields remain in place.

## Migration and data impact

No new schema migration is included. The release uses the Provider Connection, integration-binding, External Identity, Canonical Field Control, and compatibility-projection schema through migration `133`. Historical adoption is plan-first and attaches only high-confidence identities. Ambiguous or conflicting legacy rows are reported without mutation, and apply runs atomically through the authorized workspace transaction.

## Rollback guidance

Deploy the matching `3.27.4` backend and frontend together. Do not delete Provider Connections, integration bindings, External Identities, Canonical Field Controls, compatibility values, or lifecycle evidence created or observed by `3.27.5`. The schema is unchanged, and preserving those additive records keeps repeat synchronization and a later forward deployment deterministic.

## Known issues and follow-up

Compatibility provider fields remain intentionally readable until the evidence-based cutover policy is satisfied. Scheduling, source-observation history, reading-progress convergence across providers, metadata-writeback convergence, and broader work/edition/owned-copy modeling remain outside this milestone and stay in the backlog.
