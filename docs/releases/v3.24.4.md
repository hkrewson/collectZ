# collectZ v3.24.4

## Version and date

- Version: `3.24.4`
- Date: `2026-08-01`

## Milestone target and status

- Roadmap slice: `3.24.4 - Workspace-Scoped Plex Webhook Receiver`
- Status: `local implementation and verification complete; hosted gates pending`

## Summary

This release fixes Plex webhook receiver persistence by making the receiver belong to the same workspace integration row as its Plex connection. Save and refresh now retain Enabled state and masked URL readback, and incoming events carry the correct workspace and library into durable jobs.

## What changed

- Workspace Plex webhook controls now call `/api/spaces/{id}/integrations` endpoints for generation, rotation, validation, and revocation.
- Workspace integration GET and PUT responses shape receiver status from their own scoped row.
- Plex Now Playing display-token generation/revocation and display-preference saves now use the same workspace integration endpoint and row.
- Public Now Playing display tokens resolve the scoped row that owns the token, so readback uses that workspace's Plex connection.
- Incoming tokens resolve across scoped integration rows instead of checking only installation row `id=1`.
- Delivery diagnostics update the row that authenticated the receiver.
- Actionable webhook jobs include `spaceId` and `libraryId`, and duplicate suppression includes workspace identity.
- Added a focused Docker runtime smoke covering Generate, reload, Save, delivery diagnostics, scoped job enqueue, and Revoke.

## Breaking changes

- None. Migration 119 preserves the existing receiver token hash, so the URL already configured in Plex remains valid.

## Environment/config changes

- No new environment variables or credentials are required.
- The canonical development stack remains `collectz-private` on port `3201`.

## Migration and data impact

- Migration `119` moves legacy installation-level Plex receiver and Now Playing display ownership into a configured workspace only when there is exactly one safe scoped target.
- The legacy row is cleared only after the same receiver hash is present on a workspace row.
- No Plex API credential, media row, library row, or receiver token is regenerated.

## Security vulnerability triage

- High findings: none in backend or frontend production dependency audits.
- Raw receiver tokens remain one-time values and are not returned by settings reloads, logs, smoke evidence, or release artifacts.
- Token-authenticated deliveries update only the integration row that owns the matching token hash.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.4`.

## Rollback guidance

- Roll back backend and frontend together to `3.24.3`.
- Migration 119 is data-only and preserves compatible columns. Before rollback, move the receiver fields back to installation row `id=1` if the `3.24.3` global token lookup must continue receiving the existing URL.

## Known issues and follow-up

- Reload intentionally shows a masked receiver URL because the raw token is stored only as a hash.
- Installation-level receiver endpoints remain for backward compatibility, but the workspace UI no longer uses them.
- Installation-level Now Playing display endpoints also remain for backward compatibility; workspace UI actions no longer use them.
