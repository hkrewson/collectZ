## Summary

This release carries structured Blu-ray.com browser captures through review into canonical movie fallbacks, physical-edition evidence, identifiers, ownership formats, and a guarded used-price valuation.

## What changed

- Added a server-derived import mapping and compact, plain-text preview for supported browser captures.
- Used captured year and runtime as provider-enrichment hints while preserving canonical movie release-date semantics.
- Merged captured Blu-ray, 4K UHD, DVD, and digital ownership formats without removing formats already owned.
- Added an idempotent Blu-ray.com physical variant keyed by canonical media row and Blu-ray.com product ID.
- Stored the full physical-release evidence, including technical specs, ratings, release date, links, pricing, and original page metadata, in the variant record.
- Stored IMDb and ASIN identities in media metadata.
- Mapped the Blu-ray.com used-from amount to the low estimated value with currency, source, and observation time.
- Preserved manual and unrelated valuations instead of silently overwriting them.
- Paired collectZ `3.24.2` with browser extension `0.1.1`, which emits structured Blu-ray.com pricing while retaining the original Price text.

## Breaking changes

- None.

## Environment/config changes

- No new environment variables or provider credentials are required.

## Migration and data impact

- Migration `117` adds a partial unique index for one Blu-ray.com physical variant per media row and Blu-ray.com product ID.
- Existing captures are not changed until a reviewer imports them.
- Existing legacy browser captures with only the labeled Blu-ray.com Price text remain readable through a compatibility parser.
- Physical release dates and external review ratings remain source evidence on the physical variant; they do not overwrite canonical movie release dates or user ratings.

## Security vulnerability triage

- High findings: none known at implementation time.
- No production dependency changes are included in collectZ or extension `0.1.1`.
- Mapping is server-derived from retained capture evidence, scoped to the imported media row, and does not let the extension select database fields or overwrite policy.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.2`.

## Blocked or CI-only gates

- `gitleaks` and `trivy` are not installed locally. Hosted GitHub Actions remains authoritative for repository-history secret scanning, container image scanning, SBOM generation, and the complete publish workflow after this milestone is pushed.

## Rollback guidance

- Roll back the backend and frontend together to `3.24.1`.
- Imported canonical media, metadata, valuation, and physical variant rows remain valid records; rollback does not reverse completed capture imports.
- The migration adds only an index and does not remove or rewrite existing data.

## Known issues and follow-up

- Blu-ray.com page structure can change. The extension keeps original source evidence so parsing can be audited and updated without treating extracted values as authoritative provider enrichment.
