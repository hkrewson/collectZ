# collectZ v3.27.3

## Version and date

- Version: `3.27.3`
- Date: `2026-11-10`

## Milestone target and status

- Roadmap slice: `3.27.3 — Provider Identity Dual-Write, Matching, and Merge Integration`.
- Status: local release certification complete; hosted release certification remains required after an authorized push.

## Summary

Makes the provider-connection-scoped external identity registry authoritative for adopted sync paths while preserving existing provider fields as compatibility projections. The release establishes stable canonical UUIDs, lifecycle-safe provider identities, conflict-safe merge and revert behavior, canonical field precedence, and explicit cutover diagnostics without removing legacy fields.

## What changed

- Added immutable canonical object UUIDs, multi-instance Provider Connections, scoped external identities, append-only lifecycle evidence, and explicit workspace integration bindings.
- Added authorized transaction composition for identity attach, resolve, deactivate, reassign, merge, revert, compatibility projection, and canonical field decisions.
- Added plan-first, fail-closed legacy identity backfill that attaches only unambiguous evidence and reports duplicate, conflicting, or unbound rows without guessing.
- Added Canonical Field Controls so provider refreshes preserve uncontrolled existing, manual, reviewed, locked, and differently sourced values unless an explicit reviewed refresh policy permits replacement.
- Adopted authoritative reconciliation in Metron, CWA/Calibre OPDS, and Plex imports. Plex prefers GUID identity and falls back to its section/item key when a GUID is absent.
- Added bounded compatibility telemetry and deterministic cutover diagnostics. A provider requires at least seven continuous observation days, two successful syncs, no legacy activity or projection conflicts, repeat-alignment evidence, and a clean legacy inventory before a separate cutover proposal.
- Updated `fast-xml-parser` to `5.12.0` after the release audit identified the stop-node CPU-consumption advisory affecting `5.11.2`; the rebuilt backend now reports zero dependency vulnerabilities.
- Preserved compatibility fields and existing provider behavior; BookOrbit remains scoped to `3.27.4`, and Kavita authoritative adoption remains scoped to `3.27.5`.

## Breaking changes

No intended API or user-facing breaking changes. Existing provider identifiers remain readable through their compatibility fields, and no legacy field is removed.

## Environment/config changes

No new environment variables are required. Existing provider credentials remain in the encrypted workspace integration store and are not copied into identity rows or diagnostic evidence.

## Migration and data impact

Migrations `128` through `133` add canonical public UUIDs, Provider Connections, external identity relations and append-only lifecycle evidence, Canonical Field Controls, workspace integration bindings, scoped constraints, and supporting authorization policy. The migrations are additive. Ambiguous legacy values remain unchanged and require review; no compatibility provider field is deleted.

## Rollback guidance

Do not down-migrate identity lifecycle or audit tables after production writes. If application rollback is necessary, retain the additive schema and compatibility fields, deploy the matching `3.27.2` backend and frontend together, and pause provider syncs that have begun authoritative identity reconciliation until the `3.27.3` application is restored. Review any identity events recorded after deployment before retrying a failed import.

## Known issues and follow-up

Compatibility fields intentionally remain in place. A provider-specific removal proposal requires durable cutover evidence and separate review. BookOrbit OPDS support begins in `3.27.4`; Kavita authoritative identity adoption follows in `3.27.5`.
