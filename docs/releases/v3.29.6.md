## Summary

Preserves the upstream metadata provider explicitly selected by BookOrbit, together with that provider's record id, without guessing from the other identifiers BookOrbit knows about.

## What changed

- Added an optional BookOrbit native response contract at `metadataSource.provider` and `metadataSource.providerItemId`.
- Accepts attribution only when both values are present, the provider is supported, and the selected id exactly matches the provider's entry in `providerIds`.
- Keeps native metadata enrichment compatible when attribution is missing or inconsistent while refusing to claim a selected provider.
- Preserves verified attribution in BookOrbit compatibility fields and immutable provider-observation facts.
- Shows the selected metadata source separately from BookOrbit's complete provider-identifier list in Library Provider history.
- Extended BookOrbit unit, transport, authoritative import, API contract, and browser coverage.

## Breaking changes

None. The BookOrbit `metadataSource` object is optional. Existing BookOrbit servers and imports continue using OPDS/native metadata, identity, series, and cover behavior without selected-source attribution.

## Environment/config changes

None.

## Migration and data impact

No migration or backfill is required. Verified attribution is stored in existing media compatibility JSON and immutable observation facts on subsequent BookOrbit imports. Existing observations are not rewritten.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: no authorization boundary changes; attribution is written and read through the existing workspace-authorized BookOrbit import and observation paths.
- Evidence hygiene: the contract persists two bounded non-secret identifiers and never accepts credentials, endpoints, authorization values, or raw provider payloads.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.6` before release publication.

## Rollback guidance

Deploy the matching `3.29.5` backend and frontend together. No schema rollback is needed. Existing immutable observations and compatibility data remain valid; older clients simply ignore the new facts.

## Known issues and follow-up

BookOrbit must explicitly expose the selected provider and provider record id before CollectZ can preserve them. This release does not infer a provider, select one, resolve field conflicts, rematch identities, or apply historical observations.
