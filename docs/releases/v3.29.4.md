# collectZ v3.29.4

## Version and date

- Version: `3.29.4`
- Date: `2026-11-22`

## Milestone target and status

- Roadmap slice: `3.29.4 — Kavita Provider Source Observation Adoption`.
- Status: release candidate. Local implementation, canonical runtime verification, version alignment, and release gates are complete; hosted certification and automatic tag creation require an authorized push to `main`.

## Summary

Makes Kavita the second immutable provider-observation adopter, preserving separate series and chapter provenance without storing credentials or direct server URLs.

## What changed

- Added an explicit Kavita normalized-fact builder at the existing immutable observation seam.
- Kavita series and chapter reconciliation now appends `kavita_api` observations in the same authorized transaction as identity, canonical-field, compatibility, format, and normalized-metadata work.
- Observations preserve separate Kavita series/chapter identities, library and bibliographic facts, chapter-fan-out detail, and safe CollectZ cover-proxy paths.
- Queued imports derive their observation batch from the existing inline job id; synchronous imports mint one batch per request.
- Exact retries within one batch reuse the observation, while later import requests append immutable history.
- Kavita observation facts omit API keys, bearer tokens, raw API payloads, direct server/reader/cover URLs, and server filenames.

## Breaking changes

None. Kavita import routes, canonical media fields, chapter fan-out, cover and reader proxies, progress, metadata preview/apply, and integration settings remain compatible.

## Environment/config changes

None.

## Migration and data impact

No new migration is required. This release adopts the `provider_source_observations` ledger introduced by migration `145`. Existing Kavita media and identities are not backfilled or rewritten; new observations are appended by subsequent Kavita imports.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: Kavita observations use the existing actor-authorized reconciliation transaction, same-workspace relational constraints, and workspace RLS.
- Evidence hygiene: observations store safe normalized facts and CollectZ proxy paths, not Kavita API keys, bearer tokens, raw responses, direct server URLs, or server filenames.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.4` before release publication.

## Rollback guidance

Deploy the matching `3.29.3` backend and frontend together. No schema rollback is needed. Existing `kavita_api` observations remain valid immutable history and are ignored by the older application.

## Known issues and follow-up

Kavita observation adoption covers import-time series and chapter facts only. Progress reads/writes, metadata writeback, CWA, Plex, and historical backfill remain outside this release. The observation ledger does not implement public provenance readback, automated rematching, or work/edition/owned-copy modeling.
