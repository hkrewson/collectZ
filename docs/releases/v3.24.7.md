# collectZ v3.24.7

## Version and date

- Version: `3.24.7`
- Date: `2026-08-24`

## Milestone target and status

- Roadmap slice: `3.24.7 - Workspace-Owned Valuation and OCR Integrations`
- Status: `complete locally; hosted CI promotion gates pending after push`

## Summary

This release makes the workspace integration row authoritative for PriceCharting, eBay Browse, capture-image OCR, and provider-backed comic repair execution. Missing workspace settings now fail closed instead of borrowing credentials from the installation row, environment, another workspace, or an unrelated Kavita configuration.

## What changed

- Valuation refreshes now load PriceCharting and eBay settings from the workspace that owns the imported or directly refreshed media row.
- The valuation import path no longer gates execution on Kavita or falls back to installation integration row `id=1`.
- Capture-image OCR now loads the exact workspace row that owns the capture, requires explicit workspace OCR enablement, and disables environment and installation credential fallback.
- Workspace managers can configure, mask, replace, and clear Vision/OCR, PriceCharting, and eBay credentials from the workspace Integrations screen.
- Workspace integration readback identifies workspace-owned credentials separately from built-in non-secret endpoint, preset, rate-limit, header, and marketplace defaults.
- Provider-backed comic repair utilities now require `--space-id`, use workspace-only Metron/comics configuration, and restrict selected and updated media rows to that workspace.
- Added migration `120` and fresh-install parity for explicit workspace OCR enablement.
- Added unit, OpenAPI, browser, cross-workspace provider ownership, and OCR fail-closed smoke coverage.
- Associated all integration field labels with their controls so workspace credentials and existing Plex/provider settings expose stable accessible names.

## Breaking changes

- OCR is disabled unless the owning workspace has explicitly enabled it. Migration `120` preserves enabled behavior only for workspace rows that already contain explicit Vision provider configuration.
- PriceCharting/eBay and OCR execution no longer use installation-row or environment credentials when the workspace has no credential.
- `repair-comic-posters.js` and `repair-comic-issue-mismatches.js` now require an explicit positive `--space-id` argument.

## Environment/config changes

- No new environment variables are required.
- Existing `PRICECHARTING_API_KEY`, `EBAY_BROWSE_CLIENT_SECRET`, and `VISION_API_KEY` values are not inherited by workspace execution.
- Built-in non-secret provider defaults remain available and are identified as defaults in workspace integration readback.
- Analytics, metrics, and external log delivery remain installation-owned runtime integrations.

## Migration and data impact

- Migration `120` adds `app_integrations.vision_enabled BOOLEAN DEFAULT false`.
- Existing workspace rows with explicit Vision URL, provider, or encrypted key material are enabled to preserve intentional workspace configuration.
- Ambiguous installation-row valuation and OCR credentials are retained for compatibility but are not copied into a workspace and are not used by the corrected execution paths.
- No collection or media records are moved between workspaces.

- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.7`.

## Rollback guidance

- Roll back backend and frontend together to `3.24.6`.
- The additive `vision_enabled` column may remain in place; older code ignores it.
- Do not copy workspace secrets back into the installation row during rollback. If temporary OCR compatibility is required, configure the prior runtime intentionally and remove it again after returning to `3.24.7`.

## Known issues and follow-up

- Legacy installation-row provider fields remain stored for compatibility, but valuation/OCR execution ignores them. A later controlled cleanup may remove unused legacy fields after rollback compatibility is no longer required.
- Live provider calls remain operator-controlled; automated verification uses fixture or configuration-isolation paths and does not send saved credentials to third-party services.
