# collectZ v3.24.6

## Version and date

- Version: `3.24.6`
- Date: `2026-08-08`

## Milestone target and status

- Roadmap slice: `3.24.6 - Authentication Token Consumption Hardening`
- Status: `implementation and local verification complete; hosted release gates pending after push`

## Summary

This release keeps reset, invitation, and verification tokens out of query strings and makes their one-time state transitions safe under replay and concurrent requests. The browser consumes token fragments and scrubs the address bar immediately, while the backend commits token claims together with the required account, membership, session, and credential changes.

## What changed

- New reset, invitation, and verification links carry raw tokens only in URL fragments and no longer include account email addresses.
- The auth screen accepts fragment tokens, supports legacy query links during transition, and removes token-bearing URL state before rendering the form.
- Reset and verification consume payloads no longer require an email address because the hashed token identifies the account server-side.
- Password reset now conditionally claims the token, updates the password, revokes prior sessions, and creates one replacement session in a single database transaction.
- Invited registration now conditionally claims the invite and commits the new user, workspace/library memberships, default scope, and session in a single database transaction.
- Password-reset and email-verification endpoints now receive the focused authentication rate limiter.
- Added focused unit, browser, OpenAPI, and live Postgres abuse coverage for replay, concurrency, CSRF, session revocation, enumeration resistance, invalid token states, and audit token leakage.

## Breaking changes

- No operator-facing breaking change is expected.
- Custom clients consuming password reset or email verification should send only `token` plus the new password where applicable; an extra legacy email field is ignored by the current validator but is no longer required or used.

## Environment/config changes

- No new environment variables are required.
- Existing `RATE_LIMIT_AUTH_MAX` and `RATE_LIMIT_WINDOW_MS` settings now also govern password-reset and email-verification endpoints.
- The canonical development stack remains `collectz-private` on port `3201`.

## Migration and data impact

- No schema migration is required.
- Existing hashed invitation and reset/verification token rows remain compatible.
- The legacy plaintext invitation-token lookup remains temporarily available for pre-hashing migration compatibility and is not exposed by list/read responses.

## Deployment and verification

- Rebuilt the canonical `collectz-private` backend/frontend/Postgres stack in place on port `3201`; live health and Help > Releases reported `3.24.6` as the current version.
- The live Postgres auth abuse smoke proved single-winner reset, invitation, and verification claims under concurrency; password/session atomicity; replay, invalid-state, mismatch, and CSRF rejection; enumeration-resistant reset requests; and no tested raw-token material in audit details.
- Backend unit coverage passed all `350` checks. OpenAPI validation, frontend production build, API integration smoke, RBAC regression, init parity, migration rehearsal, observability evidence (`9/9`), and full browser regression (`70` passed with `4` expected homelab skips) passed.
- Isolated Core and control-plane runtime smokes passed. The standard local release gate passed; the strict full profile passed CodeQL with `5` reviewed results and `0` active findings plus Core runtime smoke, then stopped on the explicitly blocked local tools/opt-in listed below.

## Security vulnerability triage

- High findings: `0`; backend and frontend production dependency audits both passed with zero vulnerabilities.
- The backend pins the remediated `ip-address` transitive version used by the authentication limiter dependency chain.
- Raw auth tokens no longer appear in new query-string links, and conditional transactional claims prevent double consumption under concurrent requests.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.6`.

## Hosted release gates

- Pending after push: the exact hosted `compose-smoke`, `rbac-regression`, `browser-regression`, Core/control-plane `runtime-smoke`, `dependency-scan`, `secret-scan`, and `image-security-and-sbom` gates.
- Local `secret-scan` is blocked because `gitleaks` is not installed; hosted CI must scan repository history.
- Local `image-security-and-sbom` is blocked because `trivy` is not installed; hosted CI must scan the built images and emit the required SBOM artifacts.
- The full-gate browser wrapper was blocked because its opt-in bypass token was not set. The complete authenticated Playwright suite passed independently against the canonical stack, but hosted `browser-regression` remains authoritative.
- The canonical development stack intentionally uses `NODE_ENV=development` and `SESSION_COOKIE_SECURE=false`, so hosted `compose-smoke` must prove the production-shaped secure-cookie contract.

## Rollback guidance

- Roll back backend and frontend together to `3.24.5`.
- No schema rollback is required.
- Previously issued fragment links remain readable by `3.24.6`; rolling back would require reissuing links in the older query-string shape.

## Known issues and follow-up

- Security-sensitive auth audit events still need dedicated allowlisted detail schemas in a later slice.
- Identity-preserving upgrade fixtures remain a later migration-rehearsal refinement.
- Removing the legacy plaintext invite-token fallback requires a controlled migration and remains separate.
