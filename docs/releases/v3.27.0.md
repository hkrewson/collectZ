## Summary

Database workflows can now use one tested transaction executor for connection acquisition, isolation selection, commit, rollback, failed-rollback disposal, bounded retry, and sanitized diagnostics.

## What changed

- Add `executeTransaction(pool, work, options)` as the common database transaction interface.
- Limit isolation selection to PostgreSQL `READ COMMITTED`, `REPEATABLE READ`, and `SERIALIZABLE` modes.
- Keep retry disabled by default and permit at most two explicitly requested retries, only for serialization failures and deadlocks.
- Discard connections after failed `BEGIN` or failed rollback so uncertain transaction state cannot return to the pool.
- Emit optional timing/outcome diagnostics without SQL, parameters, error messages, or credentials; diagnostic sink failures cannot alter transaction results.
- Rebuild authorized saved-view scoped transactions on the executor without moving authorization into the executor.
- Adopt the interface for feature-flag default persistence as the first low-risk database-only workflow.
- Add interface tests for success, work/query/commit failure, rollback failure, disposal, isolation, bounded retries, and diagnostic sanitization.

## Breaking changes

None. Existing scoped-transaction callers keep the same interface and authorization requirements.
