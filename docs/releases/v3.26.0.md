- Status: released. Hosted release gates passed and tag `v3.26.0` was created from `main`.

## Summary

Saved library views now use database-enforced workspace, library, and owner isolation in addition to existing application authorization.

## What changed

- Bind saved-view CRUD to one authorized transaction and commit before returning an HTTP success.
- A narrowly privileged, separately authenticated scope broker grants access only to a specific runtime role, backend PID, full transaction ID, actor, workspace, and optional library. Grants expire after five minutes and are removed after work finishes.
- Enable SELECT/INSERT/UPDATE/DELETE policies on saved views; reject ownership changes and guard referential-action deletes that bypass RLS.
- Deny unscoped SQL and spoofed settings; retain existing application permission checks.
- Patch the existing `follow-redirects` overrides to `1.16.2` in both applications to clear the newly reported redirect credential-leak advisory without updating Axios.
- Certify runtime isolation, upgrade/backfill, rollback, concurrent connections, expiry, and snapshot restore in the existing PostgreSQL service locally and in hosted migration-check.

## Breaking changes

Direct runtime SQL against saved views now requires an authorized scoped transaction. Ownership fields cannot be changed by ordinary UPDATE. Other collection tables are outside this pilot.

## Environment/config changes

The migration job provisions an additional least-privilege scope-broker login. Its independent password is derived from the runtime credential using a versioned domain-separated HMAC and provisioned as a SCRAM verifier; no additional operator secret is required. Rotate the runtime credential through the migration/provisioning job and recreate the backend together. The broker has no table privileges and is never granted to the runtime role.

## Migration and data impact

Migration `124` creates an owner-only scope schema and enables saved-view RLS. Existing views with a library and missing workspace are backfilled from that library. Unresolved or inconsistent ownership stops the migration transaction with an actionable error; operators must inspect and repair those rows deliberately before retrying. Rows are not discarded or assigned a guessed workspace.

## Rollback guidance

Restore the pre-upgrade database snapshot and prior images together. The previous backend does not bind saved-view scope and cannot use saved views while migration 124 policies remain enabled. Preserve backups of role provisioning state; rerun the matching provisioner after restore. Do not disable RLS as an undocumented compatibility workaround.

## Known issues and follow-up

Broader table-family activation, background-job adoption, and other maintenance paths remain backlog work. A five-minute transaction authorization limit fails closed; do not perform provider/network work inside these short saved-view transactions. Run migration/provisioning before backend startup; legacy owner-credential startup is not a supported saved-view deployment path.
