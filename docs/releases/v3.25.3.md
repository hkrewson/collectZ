## Summary

Updates vulnerable backend runtime dependencies and frontend test tooling to patched compatible releases following fresh full dependency audits.

## What changed

- Update affected backend packages and transitive dependencies: `body-parser@2.4.0`, `multer@2.5.0`, `nodemailer@10.2.1`, `ip-address@10.7.4`, and `zod@4.6.7`.
- Update frontend `vitest` and `@vitest/mocker` to `4.1.12`.
- Preserve the established Node `24.22.1` baseline and avoid unrelated major-version migrations.
- Synchronize application metadata and Help > Releases to `3.25.3`.

## Breaking changes

No planned API or data contract changes. Dependency updates are constrained to compatible releases.

## Environment/config changes

No environment changes are planned.

## Migration and data impact

No database migration or collection data changes are planned.

## Deployment and verification

Clean backend and frontend installs completed and audited zero vulnerabilities. Backend unit tests passed (363), OpenAPI validation passed, frontend unit tests passed (4), and the Vite `8.3.5` production build passed. The canonical `collectz-private` stack reports Node `v24.22.1` and app/frontend/backend/build `3.25.3`; Help > Releases served `3.25.3` as newest. Observability release evidence passed 9/9 checks. The standard local release gate passed all 12 checks. The strict full profile reported 14 passed, 0 failed, 3 blocked: local Gitleaks is unavailable, browser regression lacks `PLAYWRIGHT_E2E_BYPASS_TOKEN`, and local image/SBOM scanning lacks Trivy. Preflight marks secure-cookie compose smoke blocked because the canonical development stack runs with `SESSION_COOKIE_SECURE=false` and `NODE_ENV=development`; hosted CI must confirm production-shaped settings.

- Advisory IDs: `GHSA-27r3-jxmh-p828` (`body-parser`); `GHSA-rxp7-6hxx-x8q5` (`ip-address`, through `express-rate-limit`); `GHSA-q7qp-rjg7-q26m` (`multer`); `GHSA-8c8m-p3m8-cjg8`, `GHSA-m943-m63m-w62w`, and `GHSA-85x2-q946-cp5h` (`nodemailer`); `GHSA-mrhx-c7xc-m3w5` (`zod`); `GHSA-qxg6-89mg-rqv8` and `GHSA-xp26-3454-mjgp` (`@vitest/mocker`/Vitest).

If a compatible dependency update causes a runtime regression, restore the prior backend/frontend image tags while retaining the database. No schema change is planned; verify migration status before restoring data from backup.
