## Summary

Makes immutable BookOrbit and Kavita source evidence safely readable through the media API and Library item drawer without exposing credentials, raw provider responses, or internal authorization state.

## What changed

- Added a newest-first, paginated provider-observation endpoint for media records in the active workspace/library scope.
- Readback includes the safe Provider Connection label/type, identity kind and lifecycle, canonical public UUID at observation time, normalized provider facts, timestamps, and stable content fingerprint.
- BookOrbit history exposes normalized native/OPDS facts and upstream provider identifiers such as ComicVine or Goodreads ids when observed.
- Kavita history preserves separate series/chapter evidence and safe CollectZ cover-proxy provenance.
- Added a bounded Provider history section to the Library item drawer.
- The projection omits workspace and actor implementation ids, identity database ids, idempotency keys, Provider Connection endpoints/settings, credentials, authorization values, and raw payloads.

## Breaking changes

None. Existing media detail, provider import, identity, cover, reader, progress, metadata writeback, and observation append contracts remain compatible.

## Environment/config changes

None.

## Migration and data impact

No migration or backfill is required. The endpoint reads the append-only `provider_source_observations` ledger introduced by migration `145`; existing observations become readable immediately and future imports continue appending history.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: media existence is verified inside the actor-authorized workspace/library transaction before observation history is queried; row-level security remains active.
- Evidence hygiene: the public DTO is an explicit allowlist and never projects credentials, endpoints, actors, scope implementation ids, idempotency keys, or raw provider responses.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.5` before release publication.

## Rollback guidance

Deploy the matching `3.29.4` backend and frontend together. No schema rollback is needed, and immutable observations remain intact for a later deployment.

## Known issues and follow-up

Readback is historical evidence, not an automated conflict decision. Historical backfill, rematching, provider selection, writeback/progress observations, additional provider adoption, and work/edition/owned-copy modeling remain separate work.
