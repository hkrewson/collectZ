- Status: `complete locally; hosted CI promotion gates pending after push`

## Summary

This release removes CollectZ's final plaintext invitation-token compatibility path. Fresh and upgraded databases now store only a required unique token hash, registration claims invitations only by that hash, and maintained migration evidence proves legacy upgrade and restore behavior without retaining usable credential material.

## What changed

- Added migration `121` to revoke legacy invitations without a usable hash, assign non-claimable retirement hashes, clear plaintext values, remove the plaintext index and column, and enforce a non-null unique hash.
- Updated the fresh-install schema to create hash-only invitations from the outset.
- Removed the plaintext fallback from invitation registration while retaining advisory-lock serialization and one-time conditional consumption.
- Updated the aggregate invitation inventory to prove column absence and hash completeness without exposing invitation identities or token material.
- Extended generic migration rehearsal evidence to capture secret-free invitation schema state before upgrade, after upgrade, and after snapshot restore.
- Updated focused unit and live abuse coverage for hash-only lookup, replay, concurrency, CSRF non-mutation, and audit hygiene.

## Breaking changes

- The `invites.token` database column is removed. Any unsupported external database integration that reads that internal column must migrate to supported application APIs.
- Rolling an older backend against the upgraded schema is unsupported; backend and frontend should be rolled forward or restored together using the documented database snapshot procedure.

## Environment/config changes

- No new environment variable is introduced.
- The canonical development stack remains `collectz-private` on port `3201`.

## Migration and data impact

- Migration `121` preserves claimability for unexpired invitations that already have a valid hash.
- Any legacy row missing a hash is revoked before receiving a deterministic, non-claimable retirement hash.
- Plaintext token values and their column are permanently removed on upgrade.
- Restore rehearsal retains the pre-upgrade snapshot as the supported rollback path because a down migration cannot recreate discarded plaintext credential material.

- Stop application writes and restore the pre-upgrade database snapshot before deploying `3.24.10` backend and frontend images.
- Do not attempt to reconstruct or repopulate plaintext invitation tokens during rollback.
- Invitations created after the snapshot must be reissued after restoration.
