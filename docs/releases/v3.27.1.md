# collectZ v3.27.1

## Version and date

- Version: `3.27.1`
- Date: `2026-11-08`

## Milestone target and status

- Roadmap slice: `3.27.1 — Canonical Object UUID and External Identity Registry`.
- Status: complete locally; hosted release gates remain pending until `main` is pushed.

## Summary

Canonical media objects now have immutable collectZ UUIDs, while provider identifiers live in a separate, workspace-safe registry scoped to stable provider connections.

## What changed

- Add a collectZ-generated `media.public_id` UUID without replacing the existing numeric primary key or internal foreign keys.
- Add multi-instance `provider_connections` with stable UUID identity, explicit active/disabled/archived lifecycle, validated provider settings, and separately stored encrypted credential payloads.
- Add provider-connection-scoped external media identities with raw and normalized values, concrete canonical media targets, first/last-seen timestamps, safe source URLs, active/deactivated history, and append-only lifecycle events.
- Enforce active identity uniqueness by workspace, provider connection, identity kind, and normalized external id, allowing two installations of the same provider to use the same local id safely.
- Add database-enforced workspace consistency between media and libraries and between external identities, provider connections, and media targets.
- Protect every new workspace-owned identity table with RLS from its first migration and route identity operations through authorized transactions.
- Add adapter-owned settings, credential, and external-id normalization contracts plus the `resolve`, `attach`, `listForMedia`, `deactivate`, and transactional `reassign` identity interface.
- Record the identity decision and rejected alternatives in `docs/adr/0001-canonical-object-and-provider-identity.md`.

## Breaking changes

None for existing media callers. Existing numeric media identifiers remain valid. The new provider-identity registry is not yet authoritative for legacy provider matching; that cutover belongs to `3.27.2`.

## Environment/config changes

None. Provider credentials continue to use the existing integration encryption capability and are never returned by provider-connection projections.

## Migration and data impact

Migrations `125`–`127` use an expand/backfill/harden sequence. Migration `125` adds UUID defaults and the RLS-protected identity relations, `126` backfills every existing media UUID, and `127` validates retained ownership before adding not-null, immutable, uniqueness, and cross-workspace constraints. The canonical retained database upgraded all 2,080 media rows with 2,080 distinct non-null UUIDs. Ambiguous legacy provider ids are intentionally not backfilled.

- Scope: tenant isolation, immutable public identity, provider credential separation, and secret-free evidence/readback.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.27.1`.

## Rollback guidance

Take a database snapshot before upgrade. To roll back application behavior, restore the pre-`125` database snapshot and deploy the matching prior backend/frontend images together. Do not drop identity tables or disable RLS as an ad hoc rollback. Migration `127` prevents cross-workspace media/library ownership and should not be reversed without first validating any writes made after upgrade.

## Known issues and follow-up

This release deliberately does not backfill ambiguous legacy provider ids, change production provider matching precedence, or add BookOrbit. `3.27.2` adopts the registry for dual-write, matching, merge, and revert behavior; `3.27.3` adds the BookOrbit OPDS adapter, including CBZ/CBR media recognition.
