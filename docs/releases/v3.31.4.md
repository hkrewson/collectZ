# collectZ v3.31.4

## Version and date

- Version: `3.31.4`
- Date: `2026-11-27`

## Milestone target and status

- Roadmap slice: `3.31.4 — Deterministic Blu-ray Format Fallback and Resumable Traversal`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Repairs two live collection-intake failures found after the resilient enrichment release. Browser companion `0.3.2` now recognizes valid Blu-ray product pages whose edition label omits the format, and advances multi-page collection traversal through persisted browser alarms so extension-worker suspension cannot strand a batch after page one.

## What changed

- Falls back from an edition-only subheading to the exact-product release title when determining media format.
- Uses the already bounded collection-row format as a final fallback when product-page format parsing remains unresolved.
- Treats deterministic parser misses as non-transient instead of repeating the same parse three times.
- Retains bounded retry only for provider challenges, network failures, throttling, forbidden responses, and server failures.
- Saves each page before scheduling the next traversal alarm and reschedules persisted collection work after browser startup or extension update.
- Preserves duplicate-safe batch page delivery if a worker stops after server delivery but before local progress is saved.

## Breaking changes

Browser companion `0.3.2` adds the standard browser `alarms` permission. The CollectZ batch payload and server API remain backward compatible.

## Environment/config changes

None. The companion continues to use the existing extension-scoped CollectZ token and the user's active Blu-ray.com session.

## Migration and data impact

No database migration is required. Existing failed rows can be retried in the same batch after companion `0.3.2` is loaded. A persisted active traversal can resume from its last saved next-page URL.

## Deployment and verification

The canonical `collectz-private` stack on port `3201` remains the runtime target. Closeout verifies the exact live failure shape, companion unit/type/build gates, version and release-feed alignment, canonical runtime health, Help > Releases, relevant RBAC/browser/runtime gates, and the standard local release gate.

## Security vulnerability triage

- High findings: none in backend or frontend production dependency audits.
- Authorization impact: unchanged exact-library actor-authorized RLS boundary.
- Session boundary: provider requests remain in the active browser session; credentials, cookies, headers, and raw HTML remain browser-local.
- Permission impact: `alarms` schedules local extension work only and grants no provider or CollectZ data access.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.4` before release publication.

## Rollback guidance

Deploy matching CollectZ `3.31.3` backend/frontend and browser companion `0.3.1`. Migration `150` remains current and compatible. Existing batch evidence remains reviewable, but affected edition-label pages may return to deterministic enrichment failure and long traversals may again strand after worker suspension.

## Known issues and follow-up

The workflow remains manually initiated and depends on Blu-ray.com markup and the user's signed-in browser session. Persistent provider challenges still require user resolution. Scheduled refresh, non-owned state mapping, price/rating history, upgrade discovery, notifications, Plex propagation, and additional providers remain backlog work.
