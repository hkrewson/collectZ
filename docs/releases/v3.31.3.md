# collectZ v3.31.3

## Version and date

- Version: `3.31.3`
- Date: `2026-11-26`

## Milestone target and status

- Roadmap slice: `3.31.3 — Resilient Blu-ray Detail Enrichment and Partial Completion`.
- Status: complete locally; hosted certification awaits an authorized push.

## Summary

Makes authenticated Blu-ray collection intake honest and recoverable when exact-product detail pages are throttled, challenged, or incomplete. Browser companion `0.3.1` applies bounded adaptive retry and can retry only failed editions in the existing batch, while CollectZ distinguishes a fully ready batch from one that is ready with issues.

## What changed

- Detects soft authentication and provider challenge pages returned with HTTP `200` instead of collapsing them into a generic parse failure.
- Retries transient detail failures up to three times with increasing delay and slower inter-item pacing.
- Preserves specific bounded detail failure reasons without storing raw private HTML, cookies, credentials, or authorization headers.
- Derives enriched and failed detail totals from batch evidence and displays `Ready with issues` with a concise recovery path.
- Lets the browser companion reload the current batch and retry only failed rows, preserving batch identity, ordering, already enriched rows, and reviewer-controlled decisions.
- Preserves an unavailable collection count as unknown rather than coercing it to zero.

## Breaking changes

None. Existing `3.31.2` batches remain readable. Failed-only retry requires browser companion `0.3.1`; failed rows remain ineligible for import until enrichment succeeds.

## Environment/config changes

None. Retry continues to use the user's active Blu-ray.com browser session and the existing extension-scoped CollectZ token.

## Migration and data impact

No database migration is required. `ready_with_issues`, enriched totals, and failed totals are derived from existing bounded item evidence. Retry upserts the same `(batch, provider item)` identities.

## Deployment and verification

The canonical `collectz-private` stack on port `3201` is the runtime target. Closeout verifies browser companion `0.3.1`, OpenAPI, backend and frontend tests/builds, partial-batch runtime smoke, failed-only retry contracts, rendered desktop/mobile partial-review evidence, Help > Releases, relevant RBAC/browser/runtime gates, and the local release gate.

## Security vulnerability triage

- High findings: none in the backend or frontend production dependency audits.
- Authorization impact: unchanged exact-library actor-authorized RLS boundary.
- Session boundary: retry executes inside the active browser session; credentials, cookies, headers, and raw HTML remain browser-local.
- Evidence boundary: failure reasons are allowlisted and bounded; detail evidence remains sanitized.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.31.3` before release publication.

## Rollback guidance

Deploy matching CollectZ `3.31.2` backend/frontend and browser companion `0.3.0`. Migration `150` remains current and compatible. Existing batches retain their review evidence, but the older UI reports the stored batch status without the derived partial-completion label.

## Known issues and follow-up

The workflow remains manually initiated and deliberately paced. A provider challenge that persists after bounded retry requires the user to resolve it in the browser before retrying again. Scheduled collection refresh, non-owned state mapping, price history, upgrade discovery, notifications, Plex propagation, and additional providers remain backlog work.
