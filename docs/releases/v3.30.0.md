## Summary

Preserves BookOrbit 3.10 edition groups as immutable, reviewable provider provenance while keeping each BookOrbit book identity and CollectZ Canonical Object distinct.

## What changed

- Accepts bounded BookOrbit edition names, first-publication years, group ids, lead status, the current edition summary, and visible sibling editions from identity-matched native detail responses.
- Represents every edition by its stable `urn:bookorbit:book:{id}` identity and rejects mismatched, duplicate, oversized, or structurally invalid groups.
- Omits BookOrbit reading progress, last-read activity, internal library ids, credentials, endpoints, and raw payloads from retained observation facts.
- Adds Provider history presentation for the observed group, current BookOrbit record, provider-selected lead, edition labels, formats, and sibling identities.
- Keeps edition relationships outside canonical metadata comparison/review/apply, duplicate merging, and identity-rematch scoring.
- Extends BookOrbit transport, authoritative import, OpenAPI, browser, and source-observation coverage for the BookOrbit 3.10 contract.

## Breaking changes

None. Older BookOrbit responses and unlinked books continue through the existing OPDS/native enrichment paths without an edition-group claim.

## Environment/config changes

None. Existing native API keys can read established edition relationships through book details. CollectZ does not call BookOrbit's edit-gated suggestion or link-mutation endpoints.

## Migration and data impact

No database migration. New successful BookOrbit native imports may append immutable Source Observations containing bounded edition provenance. Existing Canonical Objects, External Identities, series memberships, field controls, and compatibility metadata are unchanged.

## Rollback guidance

Deploy the matching `3.29.12` backend and frontend together. No schema rollback is required. Immutable observations created while `3.30.0` was active remain safe historical evidence; older application versions ignore the additive edition facts.

## Known issues and follow-up

CollectZ displays provider-owned edition relationships but does not create a CollectZ Work or Edition record, collapse Canonical Objects, rematch identities, fetch edit-gated BookOrbit suggestions, or write links back to BookOrbit. Those remain separate reviewed model and mutation decisions. Local CodeQL is blocked by an incompatible installed query pack, and local gitleaks and Trivy are unavailable; hosted CI remains authoritative for CodeQL, secret scan, and image security/SBOM.
