# collectZ v3.24.8

## Version and date

- Version: `3.24.8`
- Date: `2026-08-24`

## Milestone target and status

- Roadmap slice: `3.24.8 — Identity-Preserving Upgrade Certification`
- Status: `complete locally; hosted CI promotion gates pending after push`

## Summary

This release adds a production-migration certification that proves representative authentication and authorization state still behaves as declared before upgrade, after upgrade, and after snapshot restore. It complements schema parity and row-count rehearsal with password login, concurrent sessions, verified email, active workspace/library scope, memberships and roles, personal API credentials, service credentials, audit history, and secret-free evidence.

## What changed

- Added a runtime-generated synthetic identity fixture with two users, owner/viewer workspace and library relationships, two concurrent sessions, invitation/reset/verification lifecycle rows, audit history, a personal access token, and a service-account key.
- Added a keyed, secret-free identity manifest and explicit versioned policy for session survival or revocation, active-scope preservation or clearing, and API-credential validity or revocation.
- Added baseline, production-runner upgrade, and snapshot-restore HTTP certification through the real application server while preventing automatic startup migrations only inside the explicitly gated test harness.
- Added migration-range selection so every migration newer than the maintained certified marker is evaluated and identity-sensitive changes cannot be hidden by a later unrelated migration.
- Added CI execution and release artifact collection for identity certification alongside init parity and generic migration rehearsal.
- Replaced static migration-rehearsal identity credentials and the migration-check PostgreSQL password with runtime-derived values.
- Updated migration/release checklists and local preflight artifact readback for the new certification evidence.

## Breaking changes

- None for application users or API clients.
- Maintainers must update `backend/config/identity-upgrade-policies.json` when an identity-sensitive migration intentionally changes session, active-scope, or API-credential behavior.
- Migration CI now expects `identity-upgrade-certification-evidence.json` in tagged release artifacts.

## Environment/config changes

- No production environment variable is added.
- `IDENTITY_UPGRADE_CERTIFICATION` and `IDENTITY_CERTIFICATION_SKIP_STARTUP_MIGRATIONS` are test-harness gates and only suppress startup migrations when `NODE_ENV=test` and both flags are explicitly true.
- `IDENTITY_CERTIFICATION_ADMIN_URL`, `IDENTITY_CERTIFICATION_BASELINE_VERSION`, `IDENTITY_CERTIFICATION_MODE`, and `IDENTITY_CERTIFICATION_OUTPUT` configure local/CI certification runs.
- CI derives its disposable PostgreSQL password from the GitHub run identity instead of retaining a fixed fixture password.

## Migration and data impact

- This release adds no schema migration.
- The maintained policy marker remains migration `119`; migration `120` is selected because it changes encrypted integration configuration and passes the full identity-behavior certification.
- Certification creates temporary isolated PostgreSQL databases from synthetic data and drops them after the run. It never reads or copies production identity records.
- The generic migration rehearsal remains responsible for schema/data-count rollback evidence; identity certification adds behavioral proof for selected auth/RBAC/session migrations.

## Deployment and verification

- Forced historical certification from migration `118` and automatic certification from marker `119` both passed through migration `120`.
- Each baseline, upgrade, and restore phase preserved password login, verified email, two concurrent sessions, active scope, owner/viewer workspace and library roles, personal API access, and service-account access.
- Current init parity passed with zero mismatches; generic migration `119 -> 120` and snapshot restore rehearsal preserved counts and returned to version `119`.
- The canonical `collectz-private` stack reported `3.24.8` and served it first in Help > Releases. Canonical RBAC and cross-type isolation passed.
- The full Playwright suite passed `71` tests with `4` expected homelab-only skips. Separate Core and control-plane production-shaped runtime smokes passed.
- Observability evidence passed `9/9`; production dependency audits reported zero vulnerabilities; local CodeQL reported zero active findings after redundant password-hash fingerprinting was removed.

## Security vulnerability triage

- High findings: `0`; backend and frontend production dependency audits report zero vulnerabilities.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.8`.
- Fixture passwords, tokens, keys, session secrets, encryption keys, fingerprint keys, and derived fingerprints are generated or compared at runtime and are rejected if retained in evidence.
- Database URLs and credential-bearing commands are not written to certification evidence.

## Rollback guidance

- Roll back backend/frontend and release metadata together to `3.24.7`.
- No database rollback is required because this release adds no migration.
- Removing the CI certification step does not alter application data, but do not advance the policy marker or promote later identity-sensitive migrations without equivalent behavioral evidence.

## Known issues and follow-up

- MFA/recovery and encrypted identity material are explicitly reported as `notImplemented`; add fixtures when those product capabilities exist.
- Policy overrides are intentionally empty until a migration deliberately changes identity behavior.
- Hosted CI remains authoritative for repository-history secret scan and image/SBOM evidence.
