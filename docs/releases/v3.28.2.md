# collectZ v3.28.2

## Version and date

- Version: `3.28.2`
- Date: `2026-11-20`

## Milestone target and status

- Roadmap slice: `3.28.2 — Staged Workspace Row-Level Security Expansion`.
- Status: released. Local and hosted certification passed; backend/frontend images and annotated tag `v3.28.2` identify commit `826d2587`.

## Summary

Expands PostgreSQL row-level security across five workspace-owned operational families, including durable sync jobs, while preserving application authorization through explicit actor and narrowly bounded worker transaction grants.

## What changed

- Protected Dashboard review decisions, merge-recommendation feedback, event exclusive sources, and object relationships with ownership backfills, same-scope constraints, immutable ownership, guarded cascades, and command-appropriate policies.
- Added a private transaction-scope broker for short-lived actor grants and bounded worker grants separated by claim, recovery, lifecycle, observation, maintenance, and exact-scope ingestion actions.
- Moved durable enqueue, operator readback and cancellation, dashboard/activity readback, metrics observation, startup maintenance, Plex webhook ingestion and processing, valuation refresh, Plex reconciliation preview, and legacy inline-import paths behind their respective authorization contracts.
- Activated command-separated `sync_jobs` policies for actor SELECT/INSERT/UPDATE/DELETE and worker SELECT/INSERT/UPDATE while deliberately leaving worker DELETE unavailable.
- Preserved terminal job history, including null-library tombstones, without inventing ownership; migration `144` aborts on missing workspaces or cross-workspace libraries rather than rewriting ambiguous retained rows.
- Added fresh-database, retained-upgrade, non-owner runtime, migration/restore, RBAC, browser, workspace-isolation, worker-action, and fixture-cleanup certification for the protected families.

## Breaking changes

No intended API or user-facing breaking changes. Existing Dashboard workflows, imports, provider synchronization, Plex webhooks, job history, cancellation, metrics, and startup recovery retain their public behavior. Direct unscoped runtime SQL that previously relied on broad table privileges is intentionally denied and must use an approved actor or worker authorization path.

## Environment/config changes

No new required environment variables. The existing split migration-owner and non-owner runtime database credentials remain required. Runtime scope-broker credentials continue to be derived during provisioning and are not configured or persisted separately.

## Migration and data impact

Migrations `137` through `144` add ownership constraints, RLS policies, authorization functions, private transaction-grant tables, immutable-owner and cascade guards, and the final durable-job policy activation. Migration `144` validated all `1,078` retained jobs before activation; all had valid workspace ownership, and the single terminal null-library tombstone remains supported. The migration does not force RLS for the schema owner so reviewed migration and restore operations remain possible, while the long-lived runtime role is non-owner and cannot bypass policies.

## Rollback guidance

Deploy the matching `3.28.1` backend and frontend together. Do not delete protected ownership columns, transaction-grant functions, provider identities, durable jobs, review history, exclusive-source observations, or object relationships created or retained by `3.28.2`. Follow the reviewed migration rehearsal if a schema rollback is required; schema-owner restore remains intentionally distinct from long-lived runtime access.

## Known issues and follow-up

RLS remains staged rather than globally enabled. Authentication/bootstrap and control-plane tables, plus other workspace-owned families without family-specific worker/export/maintenance contracts, remain outside this milestone. New durable job actions or job types must update their module allowlists and policy certification before use. Platform control-plane runtime certification remains complementary to the public Core workflow for future releases.
