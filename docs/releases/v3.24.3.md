# collectZ v3.24.3

## Version and date

- Version: `3.24.3`
- Date: `2026-08-01`

## Milestone target and status

- Roadmap slice: `3.24.3 - Plex Active Webhook Listener`
- Status: `implementation complete; hosted release gates pending`

## Summary

This release makes Plex an active inbound source by accepting its documented multipart webhooks, processing new-title/watched/rating events through durable jobs, and enabling scheduled reconciliation and state readback as a fallback.

## What changed

- Added bounded multipart parsing for Plex's JSON `payload` field and optional thumbnail.
- Kept token authentication ahead of body parsing and discarded thumbnail bytes after request handling.
- Queued `library.new`, `media.scrobble`, and `media.rate` events durably with queued/running duplicate suppression.
- Reused the existing single-rating-key import for newly added Plex titles.
- Made watched and rating events read current state from Plex before applying it to matching CollectZ rows.
- Added redacted accepted/rejected delivery diagnostics to the Plex Webhook settings readback.
- Enabled reconciliation and watched/rating readback for existing configured Plex integrations and made completed new connections default to active inbound monitoring.

## Breaking changes

- None.

## Environment/config changes

- No new environment variables or credentials are required.
- Existing environment overrides for Plex reconciliation and readback scheduling remain authoritative.

## Migration and data impact

- Migration `118` adds last-attempt status, time, error, and content-type fields for Plex webhook delivery diagnostics.
- The migration enables persisted reconciliation and watched/rating readback settings for rows that already have a Plex URL, encrypted token, and selected library sections.
- On the next backend start, an already-configured integration performs its first enabled reconciliation sweep; Plex titles missing from CollectZ are added, strong-identity matches may be updated, and ambiguous matches remain in conflict review.
- No existing media row is deleted. Webhook state events update only Plex-linked rows after current Plex metadata is read back.

- The multipart receiver smoke rejected invalid tokens and malformed payloads, accepted a bounded payload plus thumbnail, deduplicated a repeated `library.new`, imported the referenced title, and applied `media.scrobble` and `media.rate` after metadata readback from the fake Plex server.

## Security vulnerability triage

- High findings: none.
- Backend and frontend production dependency audits reported zero vulnerabilities; maintained-source CodeQL reported zero active findings.
- The receiver authenticates its revocable path token before multipart parsing.
- Multipart field, file, and part counts are bounded; the optional thumbnail is not persisted.
- Receiver responses, diagnostics, jobs, activity, and release evidence must remain free of raw receiver tokens, Plex tokens, machine UUIDs, IP addresses, and media file paths.
- Owner: collectZ maintainer.
- Target remediation milestone: `3.24.3`.

## Blocked or CI-only gates

- `secret-scan` remains hosted-only because `gitleaks` is not installed locally.
- `image-security-and-sbom` remains hosted-only because `trivy` is not installed locally; the required CycloneDX artifacts must be generated in CI.
- The exact CI `compose-smoke` secure-cookie contract must run after push because the verified development stack intentionally uses `SESSION_COOKIE_SECURE=false` and `NODE_ENV=development`.
- The full local gate's browser wrapper was blocked by the absent opt-in bypass token; the complete authenticated Playwright suite independently passed 69 checks with four expected homelab-only skips.
- Hosted CI must rerun `compose-smoke`, `rbac-regression`, `browser-regression`, core/control-plane `runtime-smoke`, `dependency-scan`, `secret-scan`, and `image-security-and-sbom` before promotion.

## Rollback guidance

- Roll back backend and frontend together to `3.24.2`.
- Disable Plex reconciliation and watched/rating readback before rollback if automatic inbound monitoring is not desired on the restored version.
- Migration `118` is additive; its diagnostic columns can remain in place after application rollback.

## Known issues and follow-up

- Plex does not document a general title-update webhook, so scheduled reconciliation remains necessary.
- Five ambiguous title/year matches from the live follow-up sweep remain in Plex conflict review; they were not applied automatically.
- Legacy libraries remain separate scopes until the planned single-library migration. The active sweep imported into the current library and did not merge rows from legacy library scopes.
- Automatic CollectZ-to-Plex watched/rating writeback remains a separate follow-up.
