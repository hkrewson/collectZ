- Status: release candidate. Implementation, canonical runtime verification, version alignment, and permitted local release gates are complete; hosted certification requires an authorized push.

## Summary

Adds durable, non-mutating review decisions for individual BookOrbit and Kavita metadata differences, so provider evidence can be approved, rejected, or deferred before any future apply policy exists.

## What changed

- Added an append-only, exact-library-scoped review ledger tied to the canonical media record and immutable provider observation.
- Binds each decision to server-computed observation and current-value fingerprints so changed canonical data makes an earlier decision visibly outdated.
- Adds approve, reject, and seven-day defer actions to Library Provider history.
- Returns only the latest safe review projection; internal actor and ownership identifiers remain private.
- Rejects attempts to review unsupported, matching, absent, or no-longer-current differences.
- Extended OpenAPI, migration inventory, provider contract, unit/source checks, and the BookOrbit runtime smoke.

## Breaking changes

None. Existing provider-observation comparison fields add a nullable `review` property. Approval records review provenance only and does not apply metadata.

## Environment/config changes

None.

## Migration and data impact

Migration `146` adds `provider_observation_field_reviews`, its exact-scope foreign keys and indexes, row-level security, and append-only trigger protections. Existing media and observations are not rewritten or backfilled.

## Security vulnerability triage

- High findings: backend and frontend production dependency audits must report zero blocking vulnerabilities.
- Authorization impact: decisions are written only inside the authorized exact workspace/library transaction and are protected by same-scope foreign keys and row-level security.
- Evidence hygiene: ordinary readback omits workspace ids, library ids, actor ids, credentials, endpoints, raw payloads, and internal authorization data.
- Owner: CollectZ maintainers.
- Target remediation milestone: `3.29.8` before release publication.

## Rollback guidance

Deploy the matching `3.29.7` backend and frontend together. Migration `146` may remain in place because older code does not access the new additive table; do not delete retained review history during rollback.

## Known issues and follow-up

Review decisions are advisory. Applying approved metadata, provider-selection policy, identity rematching, and work/edition/owned-copy modeling remain separate future work.
